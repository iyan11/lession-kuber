# KubeLab — изучаем Kubernetes на Windows

**Отдельное приложение для Windows, в котором можно изучать Kubernetes и Minikube через практику во встроенной консоли.**

Урок, команды и объяснения находятся рядом. Вводишь команду, читаешь результат и разбираешься, что произошло. Если встречается знакомая ошибка, приложение подсвечивает её и предлагает следующий шаг.

> **Статус:** ранняя версия **0.1.0-alpha.3**. Исходники содержат приложение и мастер установки компонентов. Проверены тесты логики, HTTP API и браузерного интерфейса; установка на чистую Windows и реальный кластер пока не прошли полную проверку. Сборка не подписана цифровой подписью.

## Установка

Установщик **KubeLab-Setup-0.1.0-alpha.3-x64.exe** устанавливает приложение и открывает мастер подготовки компьютера. Сборки публикуются в [Releases](https://github.com/iyan11/lession-kuber/releases), когда готовы к загрузке.

| Компонент | Откуда берётся | Если уже установлен |
| --- | --- | --- |
| KubeLab и встроенный runtime | Из установщика | Обновляется приложение. Отдельный Node.js не нужен. |
| WSL 2 | Официальный MSI внутри пакета | Подходящая версия сохраняется. |
| Minikube и kubectl | Встроенные исполняемые файлы | Совместимый системный CLI используется в первую очередь; иначе — встроенная копия. |
| Docker Desktop | Ссылка и скачивание непосредственно с сайта Docker по выбору пользователя | Повторная установка пропускается. |

Мастер показывает состояние компонентов, запрашивает UAC при настройке WSL и сообщает о необходимой перезагрузке. После неё подготовку можно повторить через **«Помощь» → «Проверить установленные компоненты»** в приложении. BIOS/UEFI и аппаратную виртуализацию пользователь настраивает самостоятельно. Автоматической перезагрузки нет.

**Граница офлайн-режима:** приложение, WSL, Minikube и kubectl устанавливаются из пакета. Для скачивания отсутствующего Docker Desktop и первого получения образов Minikube/Kubernetes/Docker нужен интернет. Кэш образов кластера в этот установщик не включён. Тренажёр работает без Docker и интернета.

Docker Desktop не перераспространяется в нашем установщике. Его условия пользователь принимает в официальном продукте. SHA-256 всех пакетов закреплены в [setup/payload.lock.json](setup/payload.lock.json); для MSI WSL и установщика Docker дополнительно проверяется цифровая подпись поставщика.

## Для кого

Для тех, кто уже знаком с Docker и хочет освоить Kubernetes с нуля на своём Windows-компьютере. Умеешь собирать образы, запускать контейнеры и читать их логи — можно переходить к кластеру. Основам Docker этот курс не обучает.

На практике разберём:

- зачем нужны Pod, Deployment и Service;
- как запустить локальный кластер через Minikube;
- как масштабировать приложение, менять настройки и откатывать обновления;
- как читать логи и находить причины ошибок.

Не нужен облачный кластер. Для реальных упражнений используется локальный Minikube с Docker-драйвером.

## Как проходит обучение

В каждом уроке есть объяснение задачи, словарь новых понятий и последовательные шаги. У каждой команды разобраны параметры и ожидаемый ответ. Примеры вывода помогают отличить принятую настройку от фактической готовности приложения. В конце есть проверка результата, небольшое задание и вопрос с объяснением ответа.

За ориентир для последовательности тем использованы [Kubernetes Basics](https://kubernetes.io/docs/tutorials/kubernetes-basics/) и [Minikube Kubernetes 101](https://minikube.sigs.k8s.io/docs/tutorials/kubernetes_101/). Тексты и примеры адаптированы для локального проекта KubeLab на Windows.

1. Открываешь урок: короткое объяснение, цель и команды.
2. Вводишь команду самостоятельно или нажимаешь на пример, чтобы вставить его в консоль.
3. Запускаешь команду и видишь её вывод.
4. Если возникла ошибка — читаешь объяснение и предлагаемую команду исправления.
5. Сверяешь результат с заданием, отвечаешь на вопрос и отмечаешь урок как пройденный.

Например, при вводе `minicube` приложение подсказывает правильное название — `minikube`. Если Pod показывает `ErrImageNeverPull`, подсказка предлагает проверить тег и загрузить образ в Minikube:

```text
minikube image load kubelab:1.0 -p kubelab
```

Подсказки работают по локальным правилам и известным сообщениям ошибок. Они помогают с диагностикой, но не гарантируют определение любой неисправности.

## Два режима консоли

| Режим | Как работает | Что нужно |
| --- | --- | --- |
| **Тренажёр** | Моделирует команды и состояние учебного кластера. Не запускает процессы и не меняет компьютер. | Само приложение. Docker и кластер не нужны. |
| **Реальные команды** | Запускает установленные `docker`, `minikube` и `kubectl`. Показывает настоящий вывод. Команды действительно меняют контейнеры и ресурсы кластера. | Docker Desktop, Minikube и kubectl. |

По умолчанию включён тренажёр. Его модель упрощена и поддерживает команды курса, а не весь синтаксис Kubernetes.

Встроенная консоль предназначена для работы с этими тремя CLI. Это не полноценный PowerShell: конвейеры, перенаправления, интерактивный `-it` и внешние редакторы внутри неё не поддерживаются.

## Что есть в приложении

- Русский интерфейс и семь практических уроков.
- Поле ввода команд с подсветкой некоторых ошибок синтаксиса.
- Вывод команд по мере выполнения, выделение ошибок и код завершения процесса.
- Объяснения типовых проблем: отсутствующий образ, недоступный Docker, отсутствующий профиль Minikube, занятый порт, `CrashLoopBackOff`.
- История команд по **↑ / ↓** и дополнение команд курса по **Tab**.
- Кнопка **«Стоп»** для длительных команд, например `port-forward`.
- Выбор рабочей папки проекта.
- Шпаргалка с поиском, схема учебного стенда и локальный прогресс обучения.

Прогресс отмечается самим учеником после практики и правильного ответа на вопрос. Автоматической проверки реального кластера пока нет.

## Приложение само становится учебным стендом

В проекте есть небольшое веб-приложение, которое можно собрать в Docker-образ и развернуть в Minikube. На нём изучаются реальные объекты Kubernetes.

```text
Windows
└── Docker Desktop · Linux containers
    └── Minikube · профиль kubelab
        └── Namespace kubelab
            ├── Deployment → ReplicaSet → Pod приложения
            ├── Service → доступ к готовым Pod
            └── ConfigMap → настройки контейнеров
```

Его API `/api/runtime` показывает имя Pod, namespace, версию, сообщение из настроек, время работы и счётчик запросов процесса. Так можно увидеть последствия перезапуска и обновления приложения.

Для доступа с Windows используется `kubectl port-forward`. Такой туннель связан с одним выбранным Pod и сам по себе не демонстрирует балансировку между репликами.

## Что понадобится на Windows

**Для тренажёра:** готовая сборка приложения — после публикации первого релиза.

**Для работы с настоящим кластером:**

1. Docker Desktop с WSL 2 backend и режимом **Linux containers**.
2. Minikube.
3. kubectl, доступный через `PATH`.
4. Интернет для первого скачивания компонентов и образов.
5. Ресурсы для Windows, Docker и кластера: учебный профиль настроен на **2 CPU и 3072 МБ RAM**. Это ресурсы профиля, а не общие требования ко всему компьютеру.

Включать встроенный Kubernetes в Docker Desktop для этого курса не требуется. Minikube создаёт собственный учебный кластер.

## Запуск из исходников

Нужен Node.js 22.12 или новее. Из PowerShell:

```powershell
git clone https://github.com/iyan11/lession-kuber.git
cd lession-kuber
npm install
npm start
```

Для точного воспроизведения зависимостей используй pnpm и `pnpm install --frozen-lockfile`. `npm test` запускает проверки. `npm run web` открывает браузерную версию тренажёра на http://127.0.0.1:3000; реальные команды доступны только в desktop-приложении.

Сборка установщика: сначала `npm run fetch:offline`, затем `npm run build:win`. Первая команда скачивает официальные пакеты и проверяет закреплённые SHA-256; вторая собирает NSIS-установщик в `release/`. Docker Desktop при сборке не скачивается и не включается в пакет.

Подробности: [запуск учебного стенда](RUNNING.md), [установщик и диагностика](setup/README.md).

## Обновления

Начиная с **0.1.0-alpha.2**, KubeLab проверяет релизы GitHub при запуске и каждые шесть часов. Кнопка **«Обновления»** позволяет проверить вручную, скачать новую версию и выбрать **«Установить и перезапустить»**. Скачивание и установка не происходят без нажатия пользователя. Обновление недоступно, пока выполняется CLI-команда или открыт мастер настройки системы.

Используется стандартный electron-updater с дифференциальной загрузкой: при наличии кэшированного установщика и blockmap скачиваются изменившиеся блоки. Если кэша или блоков нет либо сервер не поддерживает нужные запросы, загрузка переключается на полный установщик. WSL и Docker повторно не устанавливаются, мастер зависимостей при автообновлении не открывается. Прогресс обучения сохраняется в данных приложения.

**Переход с alpha.1:** установите alpha.2 или более новый выпуск вручную один раз — в alpha.1 обновлятора нет. Для следующих выпусков достаточно встроенной кнопки. Alpha-версия получает предварительные выпуски; откат на более старую версию запрещён. Для автообновлений в каждом релизе нужны `.exe`, `.exe.blockmap` и `alpha.yml` (или соответствующий канал `.yml`).

Проверяется SHA-512 скачанного установщика из метаданных, полученных по HTTPS от GitHub. Текущие alpha-сборки не имеют Windows Authenticode-подписи разработчика. Полный цикл установки обновления на отдельной Windows/VM пока не проверен.

## Техническая основа

- **Electron** — отдельное окно Windows-приложения.
- **JavaScript, HTML и CSS** — интерфейс, уроки и тренажёр.
- **Node.js** — запуск CLI и учебный HTTP-сервер.
- **Dockerfile и YAML-манифесты Kubernetes** — практические упражнения.
- **Локальные правила** — подсказки без внешнего AI API.

Аккаунт для обучения не нужен. Прогресс хранится на компьютере пользователя. Приложение не отправляет историю команд во внешний AI-сервис; в реальном режиме сами CLI могут обращаться к настроенным кластерам и реестрам образов.
