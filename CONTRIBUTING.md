# Как помочь KubeLab

Можно исправлять код, дополнять уроки, улучшать интерфейс и сообщать об ошибках. Для этого не нужен доступ на запись в основной репозиторий. Изменения принимаются через pull request; владелец проекта проверяет их перед включением в `main`.

## С чего начать

- Нашли ошибку в приложении — [создайте задачу](https://github.com/iyan11/lession-kuber/issues/new/choose), укажите версию и шаги повторения.
- Непонятен текст урока — выберите шаблон «Ошибка или непонятное место в уроке» и приведите конкретный шаг.
- Хотите написать код — посмотрите [планы проекта](ROADMAP.md). Для большой переделки сначала откройте задачу и обсудите ожидаемый результат. Исправление опечатки можно сразу прислать как pull request.

Обсуждаем изменения спокойно и по существу. Критика кода и объяснений полезна; оскорбления участников — нет.

## Своя копия и ветка

1. Нажмите **Fork** на странице репозитория. GitHub создаст копию в вашем аккаунте.
2. Склонируйте её. Замените `YOUR-LOGIN` своим именем на GitHub:

```powershell
git clone https://github.com/YOUR-LOGIN/lession-kuber.git
cd lession-kuber
git remote add upstream https://github.com/iyan11/lession-kuber.git
git switch -c fix/lesson-explanation
```

Для небольшой текстовой правки можно открыть файл на GitHub, нажать кнопку редактирования и предложить изменение через pull request.

## Запуск из исходников

Нужны Node.js 22.12+ и pnpm 11.25.0. Версии Electron и остальных зависимостей закреплены в `package.json` и `pnpm-lock.yaml`.

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm start
```

Первая установка зависимостей скачает Electron. Для работы над текстами, интерфейсом и тренажёром Docker и Minikube не нужны. Браузерный просмотр:

```powershell
pnpm run web
```

Откройте http://127.0.0.1:3000. Реальные команды, защищённое хранение API-ключей и обновления доступны только в desktop-приложении. В режиме разработки проверка обновлений отключена; тесты используют подставные ответы и не обращаются к платным API.

## Перед отправкой

- Одна понятная задача на pull request. Объясните, что изменилось для ученика.
- Для кода запустите `pnpm test`. Для небольшого изменения текста достаточно перечитать его в интерфейсе. Если меняются команды урока, проверьте соответствующий сценарий тренажёра.
- Для интерфейса приложите снимок экрана. Для исправления ошибки опишите исходный пример и результат после исправления.
- Укажите, что проверили вручную и что не удалось проверить. Прохождение тестов не доказывает работу настоящего кластера или установщика Windows.
- Для урока объясняйте задачу, команду, её параметры и ожидаемый результат. Docker считается знакомой темой. Команды курса адресуются профилю и контексту `kubelab`; объекты приложения — namespace `kubelab`. Перед удалением объектов опишите последствия.
- Не добавляйте API-ключи, kubeconfig, `.env`, личные пути, логи с секретами, установщики и скачанные зависимости. `node_modules/`, `payload/`, `.lab/` и `release/` не входят в исходники.
- Не отключайте проверку TLS, sandbox Electron и проверку отправителя IPC. Ответ модели — текст для чтения, без автоматического выполнения команд.
- Не меняйте версию приложения ради обычного исправления: номер выпуска выбирает сопровождающий перед релизом.

## Отправить pull request

```powershell
git add public/lessons.js
git commit -m "docs: clarify the explanation of kubectl context"
git push -u origin fix/lesson-explanation
```

Вместо `public/lessons.js` укажите свои изменённые файлы. На GitHub откройте pull request из своей ветки в `iyan11/lession-kuber:main`. Заполните описание: проблема, изменение, проверка. После замечаний добавляйте коммиты в ту же ветку — pull request обновится.

Чтобы получить новые изменения исходного проекта:

```powershell
git fetch upstream
git switch main
git merge --ff-only upstream/main
```

## Сборка Windows-установщика

Для обычной правки полный установщик собирать не нужно. Если меняете упаковку или подготовку Windows, используйте Windows x64:

```powershell
pnpm run fetch:offline
pnpm run build:win
```

Скрипт скачает большие официальные пакеты WSL, Minikube и kubectl, проверит контрольные суммы и соберёт NSIS-установщик в `release/`. Docker Desktop в пакет не включается. Скрипт сборки не публикует релиз и не запускает установщик. Подробности — [setup/README.md](setup/README.md).
