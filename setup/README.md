# Как работает установщик KubeLab

Целевая архитектура — Windows x64. Это обычный NSIS-мастер: выбор папки, установка приложения, затем окно подготовки компонентов. Приложение содержит Electron/runtime; Node.js для конечного пользователя не устанавливается.

## Компоненты

- **WSL 3.0.3.0 x64** — официальный MSI в установщике. При версии WSL не ниже 2.1.5 повторная установка MSI пропускается. Системный worker проверяет VirtualMachinePlatform, включает недостающее с `-NoRestart -LimitAccess`. Если Windows не содержит необходимых файлов компонентов, мастер сообщит об ошибке; он не обещает достать их без сети.
- **Minikube 1.39.0 / kubectl 1.36.1** — отдельные exe в ресурсах приложения. Они не перезаписывают глобальные CLI. Совместимые версии из PATH используются в первую очередь. Для kubectl допускаются minor 1.36–1.38 относительно Kubernetes 1.37 в выбранной версии Minikube.
- **Docker Desktop 4.97.0** — отсутствует в ресурсах установщика. Мастер предлагает официальный сайт и опциональное скачивание с desktop.docker.com. Проверяются SHA-256 и Authenticode. Официальный установщик запускается с `install --user --backend=wsl-2`, без автоматического принятия лицензии. При наличии Docker Desktop установка пропускается.

Версии и контрольные суммы: [payload.lock.json](payload.lock.json). Обновление закреплённых версий выполняется разработчиком после проверки.

## Права, перезагрузка, повторный запуск

Если WSL, Docker Desktop, Minikube и kubectl уже установлены, окно меняется на **«Все компоненты установлены»**. Остаётся одна кнопка **«Закрыть»**. Остановленный Docker Engine не считается отсутствующим Docker: в этом случае мастер предлагает запустить уже установленный Docker Desktop, а не устанавливать его заново. При необходимости перезагрузки показывается отдельный итоговый экран.

В основном окне KubeLab отдельной кнопки настройки больше нет. Повторная проверка находится в **«Помощь» → «Проверить установленные компоненты»** и нужна только после перезагрузки или при неисправности окружения.

KubeLab устанавливается для текущего пользователя. Само приложение и реальные команды не требуют запуска KubeLab от администратора. Отдельный worker настройки компонентов WSL запрашивает UAC; отмена UAC не удаляет приложение. Установка Docker выполняется в пользовательском режиме. Перед скачиванием его можно отключить флажком.

При коде MSI 3010/1641 или отложенном включении компонентов мастер сообщает о перезагрузке и останавливает дальнейшую подготовку. Автоматического reboot или RunOnce нет. После перезагрузки: KubeLab → «Помощь» → «Проверить установленные компоненты» → «Установить недостающее». Проверка выполняется заново, готовые компоненты пропускаются.

При установке невозможна автоматическая настройка BIOS/UEFI. На поддерживаемом компьютере нужна включённая виртуализация. Windows Server не поддерживается. Требования Docker Desktop и Windows могут меняться; сверяйся с [официальной документацией](https://docs.docker.com/desktop/setup/install/windows-install/).

Логи системного worker: `%ProgramData%\KubeLab\Setup\prerequisites.log` и `wsl-msi.log`. Эти журналы остаются локальными и не загружаются в GitHub.

Удаление KubeLab удаляет приложение и его встроенные CLI. Оно не удаляет системный WSL, Docker Desktop, существующие контейнеры и пользовательские кластеры.

## Что означает «офлайн»

Установщик содержит приложение, WSL MSI, Minikube и kubectl. Docker Desktop требует отдельного скачивания или предварительной установки пользователем. Образы Node, Kubernetes и базового контейнера Minikube в установщик не входят. Первый реальный запуск учебного кластера требует сети. Полностью автономно работает режим тренажёра.

## Сборка и проверка

```powershell
npm install
npm test
npm run fetch:offline
npm run build:win
```

Сборка не запускает системные установщики. `fetch:offline` использует только официальные URL из manifest. В Git не попадают `payload/`, `.lab/`, `node_modules/`, `release/` и `.partial`.

Для диагностики без изменения системы:

```powershell
powershell -NoProfile -File setup/Prerequisites.ps1 -Inspect
```

`-LibraryOnly` загружает только функции для тестирования. Единственный путь включения компонентов Windows — `-SystemInstall`, который требует администратора. Обычное открытие мастера ничего не устанавливает до нажатия пользователем кнопки.

Перед стабильным релизом нужна проверка на отдельной чистой Windows/VM: отсутствующие компоненты, уже установленный Docker, отмена UAC, отсутствие интернета, перезагрузка и повторный запуск. Разработческие проверки не заменяют этот сценарий.
